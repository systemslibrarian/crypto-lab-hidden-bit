## Hero (three roles, kept distinct)

- Title: `Hidden Bit`
- Subtitle: `Security games · IND-CPA · IND-CCA2 · EUF-CMA`
- Description: Flip the challenger's hidden bit, hand the adversary its oracle, and watch its advantage climb to one against textbook RSA and flatline against RSA-OAEP over a thousand real trials.
- Why it matters: Every "provably secure" claim in this lab is a sentence about a game like this one. Knowing what the game can show — a break — and what it cannot — safety — is the difference between reading a security proof and being reassured by a histogram.

## §1 sections

**SCOPE** — as in the brief. Each non-goal gets its "what this isn't" line; the "secure" prohibition is a UI rule, not a non-goal: the neutral verdict text is fixed.

**SECURITY / CORRECTNESS INVARIANTS**
1. The challenger's bit comes from `crypto.getRandomValues`. The adversary never receives b, a secret key, or the decryption of the challenge; the CCA oracle rejects the challenge ciphertext by byte comparison and the rejection is shown.
2. Adversaries live in `src/adversaries/` and import only the public oracle interface. A unit test parses those files and fails if any references the challenger's internals.
3. Advantage is 2·wins/trials − 1 with a Wilson 95% interval. The neutral verdict is the fixed string "NO ADVANTAGE FOUND BY THESE ADVERSARIES"; the claims suite asserts the page never renders "secure".
4. Real primitives only: AES via WebCrypto (CBC/CTR/GCM) and a named library for ECB, with FIPS 197 vectors; RSA keys from WebCrypto exported to JWK so the same n, e, d serve textbook RSA (hand-rolled BigInt modexp) and RSA-OAEP/PSS (WebCrypto); ElGamal hand-rolled over ristretto255 with messages as hash-to-group labelled points; ECDSA with RFC 6979 vectors and Ed25519 with RFC 8032 vectors. State every KAT count.
5. BROKEN schemes are labelled in the picker and never the default; the default scheme in every game is a randomized, unbroken one.
6. Fail-closed: an oracle exception aborts the trial loop, names the cause, and does not advance the trial counter (wins + losses + errors = trials, always).
7. ECDSA is verified two ways, plain (`lowS: false`) and low-S; the page states that the library default is low-S and why the plain verifier is the one the malleation act targets.

**ARCHITECTURE** — `src/game/challenger.ts` (generic experiment, typed oracles per game), `src/game/advantage.ts` (estimate + interval), `src/schemes/{rsa-textbook,rsa-oaep,rsa-pss,elgamal,aes-modes,ecdsa,ed25519}.ts`, `src/adversaries/*.ts` (one pure strategy per file), `src/reduction/ddh.ts`, `src/prf/switching.ts` (lazy sampler), `src/ui/`.

**UI** — Central metaphor: the challenger's sealed coin. A two-column stage; the coin sits face-down on the challenger's side, oracle queries flow right and answers flow left, and each trial ends with the coin turning face-up beside the guess. A histogram and the advantage bar accumulate. Controls: game picker, scheme picker (BROKEN labels), adversary picker, trials (10–5,000), Run / Stop, and "Step one trial" that shows every intermediate value. Core interaction: textbook RSA + "re-encrypt and compare" reaches 1.00 within a few trials; switch to RSA-OAEP and the same adversary flatlines; the page then shows the neutral verdict and a one-line "what a flat line does and does not prove". The reduction act: pick any act-2 adversary, press "Wrap in B", and read B's DDH advantage beside A's IND-CPA advantage.

**VISUAL SEMANTICS** — The advantage bar runs 0 → 1. An advantage the interval places clearly above 0 renders as ALARM (icon, "BROKEN: advantage x ± y", red). Near zero renders NEUTRAL (grey, ring icon, the fixed neutral string) — never green. Green is reserved for KAT and consistency panels. In act 5, the plain verifier accepting the malleated ECDSA signature is ALARM with the twin verdict "VERIFIES — AND IS A NEW SIGNATURE ON A QUERIED MESSAGE"; the low-S verifier rejecting it is green. In act 6, a measured curve above the bound is ALARM (it would mean the sampler is wrong), and a claims test asserts measured ≤ bound + tolerance. Every state is icon + text + colour; check in grayscale and deuteranopia.

**EDGE CASES** — m0 = m1 (refuse: advantage undefined; tooltip); unequal-length messages in IND-CPA (refuse; tooltip on why length is outside what CPA hides); CCA query equal to the challenge (refuse; tooltip "the trivial win"); trials < 10 (warn: interval meaningless); textbook RSA with m ≥ n (refuse); EUF-CMA "forgery" on an already-queried message (not a forgery under EUF-CMA; tooltip on EUF vs SUF); PRP/PRF with q > 2^n (refuse); ElGamal message outside the labelled set (refuse; state the encoding).

**EXTENSION SEAMS** — `// [extension] point` at the adversary interface (a sandboxed visitor-authored adversary), at the scheme registry (ML-KEM IND-CCA, cross-link KEM Trap), and in `src/reduction/` (a second reduction, PRF ⇒ MAC).

## Claims suite and negative claim

`e2e/claims.spec.ts`: recompute advantage from the parsed wins and trials; assert wins + losses + errors = trials; textbook RSA + "re-encrypt and compare" gives advantage exactly 1 with zero losses; recompute (r, n − s) from the displayed (r, s, n) and assert the plain verifier's verdict is "accepted" with the ALARM text present; assert B's displayed DDH advantage equals half of A's displayed IND-CPA advantage within the displayed interval (fix that factor in the page's definition text and test against it); for each displayed q in act 6, recompute q(q − 1)/2^(n+1) and assert it matches the displayed bound and that measured ≤ bound + tolerance; retirement (change scheme → histogram and verdict reset, and the page says so); no-op guard; the `[hidden]` probe.

**Negative claim (§4.1d):** "A measured advantage near zero shows that these adversaries failed; it is not evidence that the scheme is IND-CPA secure." **Fixture:** scheme = AES-CBC with chained IV (BROKEN), adversaries = random guess and re-encrypt-and-compare; both flatline; every KAT panel green; the verdict reads "NO ADVANTAGE FOUND BY THESE ADVERSARIES — AND THE SCHEME IS BROKEN" with the negative-claim sentence beside it. The test drives to that state, asserts the neutral verdict and the twin text, then selects the BEAST-style predictor and asserts its advantage exceeds 0.9. (Predictor: after seeing the challenge, whose last block is the next IV, query m0[0] ⊕ IV_challenge ⊕ IV_next; the oracle's first block equals the challenge's first block iff b = 0.) Delete the negative-claim text and the test must fail; break a KAT inside the fixture and it must fail.
